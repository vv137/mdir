# Hybrid CPU execution: MPI, OpenMP, and SIMD

Status: fixed-layout reference implementation and validation complete.
D[cpu-hybrid-lj], 2026-10-04.
Issue #33 is the first fixed-layout Lennard-Jones slice. The broader
`md_dist` contract remains the design of PR #32, not implemented by this
prototype.

The first path separates MPI-owned centers from owned-plus-ghost reads,
uses the existing `md_exec.pair_for` CPU lowering with OpenMP over centers,
and adds an explicit opt-in SIMD width for neighbor arithmetic. MPI remains
outside OpenMP regions (`MPI_THREAD_FUNNELED`). Coordinates and IDs are
exchanged through a fixed owner–replica map; no ghost is integrated. The
first executable evaluates a fixed snapshot, not a production trajectory.

## Interface and scope

An optional CMake switch `MDIR_ENABLE_MPI=ON` builds `mdir-cpu-lj` as an
experimental build-tree tool. Default builds and `mdir run` remain unchanged.
There are no new control-file keys. The tool reads a small text snapshot:
`N Lx Ly Lz cutoff sigma epsilon`, followed by `N` rows `id x y z` in reduced
LJ units. IDs are unique, coordinates are canonical, the cell is fixed and
orthorhombic, and cutoff is below half the smallest cell edge. No topology,
PME, constraints, species mixing, checkpoint, or migration is accepted.

Options select mixed/double precision, OpenMP thread count, and SIMD width
1/4/8. Results go to stdout; the tool does not overwrite output files.
The MPI map uses periodic x slabs and direct peer exchanges, including
cutoffs spanning multiple slabs. This is a correctness baseline with
all-pairs local candidate construction and no scaling claim.

The implementation adds a checked storage-form neighbor view whose row
count is the owned-center count while indices address the local coordinate
buffer. SIMD widening supports an explicit arithmetic subset and rejects
unsupported kernels. Ordinary CPU/GPU lowering retains its default path.

## Development sequence

1. External neighbor rows, CPU SIMD arithmetic, and negative IR tests.
2. MPI fixed-map transport and a JIT driver using the same CPU lowering.
3. Independent scalar all-pairs energy, force, and virial oracle; rank/thread/
   width variations, empty ranks, periodic boundaries, tail lanes, and
   mixed/double validation. Inspect generated vector IR and machine code.
4. General field/version/contribution verifier and stage extraction through
   `md_dist`, then temporal validity, sorting/migration, EAM, and molecular
   terms. This prototype does not certify those later contracts.
5. Nonblocking transport with explicit buffer borrows and completion, then
   overlap. Start with separate pack buffers; send permits shared reads but
   forbids writes, receive forbids access before completion. General alias-
   scoped capabilities and irregular subset proofs are later work.

Numerical acceptance uses independent enumeration and analytic LJ formulas.
Record exact reference quantities, absolute/relative tolerances, max/RMS
force error, virial error, and separate CPU/GPU applicability in the PR.
Rank-count-independent bitwise results are not promised. SIMD width is an
explicit reduction-order choice; fixed width and layout preserve the
existing fixed-order OpenMP reduction strategy.

## Implemented slice

The exact code path, memory layout, precision rules, and reproduction commands
are in [cpu-hybrid-lj.md](cpu-hybrid-lj.md). This is a manually constructed
fixed-layout transport plan. MPI calls live in the experimental C++ executable;
they are not generated by `md_dist` or an upstream MPI conversion pass.

The next architecture step preserves `mdrt.event` as a logical completion
contract, independent of transport requests. Separate guarantees cover source
buffer release and consumer readiness after transfer, unpack, and visibility.
A future backend may use MPI, UCX, or NVSHMEM; the shared contract must also
record execution location and memory access regions. Open MPI and MPICH are
implementations of the MPI backend, not separate semantic dialects. This does
not assume binary compatibility between their installations.

For structured storage, a later hazard analysis can normalize subviews to a
common base and use MLIR ValueBounds slice overlap queries. Unknown overlap
requires serialization or packing. Particle index sets require additional
partition evidence. Completing a read borrow does not grant write ownership;
all aliases and outstanding accesses must still be accounted for. Neither a
capability verifier nor asynchronous transport is implemented by this slice.
