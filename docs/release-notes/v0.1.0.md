# MDIR 0.1.0

The first release of MDIR, at the end of its first milestone (M1).

## What MDIR is

MDIR is a compiler for molecular dynamics, built on MLIR. A run is written
in dialects of molecular dynamics: its potential, its integrator, its
constraints, and its couplings. MDIR derives the forces and the virial by
semantic differentiation, chooses neighbor structures, storage, and
precision, fuses loops, and lowers the result to the CPU with OpenMP or to
an NVIDIA GPU. It compiles once, just before the run, for the system at
hand. A driver, `mdir`, reads a control file in TOML with Amber, GROMACS,
or CHARMM inputs, and writes a log, files of energies, trajectories, and
checkpoints.

On an RTX 3090 it runs every system of the Amber GPU benchmark suite at
104% to 132% of the rate of pmemd.cuda (Amber 26), with the same cutoff,
PME parameters, and constraints. The white paper attached to this release
derives the methods and gives the validation and the measurements.

## Installing

- **The binary tarball.** `mdir-0.1.0-manylinux_2_28_x86_64.tar.gz` runs on
  Linux x86-64 with glibc 2.28 or later: RHEL, Rocky, and Alma 8 and later,
  Ubuntu 20.04 and later, Debian 11 and later. Extract it anywhere and run
  `bin/mdir doctor`. It carries HDF5, cuFFT, the OpenMP runtime, and
  libdevice, so a GPU run needs only an NVIDIA driver that supports CUDA
  13.0; no CUDA toolkit and no `CUDA_ROOT` (D177).
- **From source.** Download the source archive of the release. Build
  LLVM/MLIR 23.1.2 (`scripts/build-llvm.sh`), HDF5 (`scripts/build-hdf5.sh`),
  and MDIR as [README.md](../../README.md) describes, then
  `cmake --install build --prefix <prefix>`. Check the installation with
  `<prefix>/bin/mdir doctor`.
- **In a container.** Build the image with `packaging/Dockerfile`, or for
  Apptainer with `packaging/mdir.def`. Run it with `docker run --gpus all`
  or `apptainer run --nv` ([packaging/README.md](../../packaging/README.md)).
  The CUDA of the image (13.0 by default) must not be newer than the host
  driver supports. The recipe orders its layers from what changes least
  (the base image, HDF5, LLVM) to MDIR's sources, so a rebuild after a
  change to MDIR reuses the LLVM layer; Apptainer's image is made from the
  Docker image.
- **Requirements.** Linux on x86-64. For GPUs: an NVIDIA GPU and its
  driver; a build from source or the container also needs a CUDA toolkit
  (11.2 and 13.x are known to work), which the binary tarball does not.

## What is validated, and against what

| What | Compared with |
|---|---|
| Every bonded and nonbonded term, PME, and the virial, for Amber force fields | sander and pmemd (Amber 26), GROMACS 2026.3 |
| CHARMM36m terms: Urey–Bradley angles, impropers, CMAP, force switch, the switch in r² (VSWITCH), NBFIX | CHARMM 51b1, GROMACS 2026.3 |
| Triclinic cells at constant volume and pressure | sander, GROMACS 2026.3, CHARMM 51b1 |
| Custom terms; generalized Born; LJ-PME; free energy (dH/dλ and the energies of the states) | OpenMM 8.6.1 |
| The hydration free energy of ethanol in TIP3P, 14 states, MBAR: 2.793 ± 0.109 kcal/mol against 2.783 ± 0.112 | OpenMM 8.6.1 with the same Hamiltonian and protocol |
| Continuation from a checkpoint, bit for bit, for every integrator, thermostat, and barostat; on the CPU with any number of threads | an uninterrupted run |
| Thermostats and barostats: distributions of the kinetic energy and the volume, and the conserved energy | the canonical and isothermal–isobaric ensembles, GROMACS 2026.3, OpenMM 8.6.1 |
| Speed | pmemd.cuda (Amber 26) on the Amber 24 GPU benchmark suite |

Each comparison is pinned by a test that names the program and the value
it gave; Section 9 of the white paper collects them. The full list of
features and limitations is in [CHANGELOG.md](../../CHANGELOG.md).

## Compatibility in 0.x

MDIR follows Semantic Versioning. Before 1.0:

- **The control file** may change between minor versions (0.1 to 0.2).
  A key that is removed or renamed is an error that names it. It is not
  ignored.
- **The checkpoint format** is versioned in the file. A checkpoint of a
  format that a release does not read is refused with a message. It is
  never read as another format.
- **Outputs** (logs, files of energies, the run manifest) may gain
  columns or fields. The run manifest carries its own schema version.
- **Every breaking change** is listed in CHANGELOG.md with what a user has
  to do.

Patch versions (0.1.x) fix defects without changing any of these.

## Known limitations

- A run uses one CPU or one GPU. Distributed runs are milestone M4.
- Learned potentials (milestone M3) and polarizable models are not
  supported.
- Terms over triplets run on the CPU only.
- Free energy is limited to decoupling a selection, with a plain or
  shifted Lennard-Jones; on a GPU in mixed precision with the shift, dH/dλ
  of the Lennard-Jones differs by about 5e-4 kcal/mol (#48).
- On a GPU, a per-step field of the particles feeding the reciprocal sum
  gives positions that are not numbers when the particles are reordered
  (#26); free energy avoids it, and no other feature uses the pattern.
- The barostat scales the axes of the cell but does not shear it.

## Defects found after the release

- In a triclinic cell with the neighbor matrix, a run at constant pressure
  whose cell shrinks until the least of $a_x, b_y, c_z$ is below twice
  `pairlist_distance` loses pairs that enter the cutoff (#258): keep the
  least of the diagonal at least twice the pairlist distance, or use a
  later version (see `CHANGELOG.md`, Fixed).
- With the groups in an orthorhombic cell, a pairlist distance of more than
  about the edge of the cell less the half-width of a group, a skin of
  about half the cell, loses pairs, and nothing refuses it (#263): keep
  the pairlist distance well below the edge, as every ordinary input does,
  or use a later version.
