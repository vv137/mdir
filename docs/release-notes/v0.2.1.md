# MDIR 0.2.1

A patch release of 0.2.0. It fixes three defects found after 0.2.0 and
ships the packages that 0.2.0 left out: a binary tarball and Python wheels
for manylinux_2_28. The full list is in [CHANGELOG.md](../../CHANGELOG.md),
section [0.2.1].

## What is fixed

- **Large seeds in the fingerprint** (D347, #620). The fingerprint of a
  checkpoint wrote its integers through a double, so seeds of $2^{53}$ or
  more that differed could have one text, and `--continue` (or a Python
  continuation) took a changed large seed for the same run. They are now
  written exactly.
- **Python access across threads** (D346, #621). Reading `sim.tunables`
  from another thread during an update gives the values, version, and
  history of before, whole, and `sim.tunables.snapshot()` returns the three
  at once. A buffer handed to a consumer's stream keeps the simulation from
  running even if its view is released during the hand-off.
- **Device memory after a run** (D348, #622). On a GPU, a run with more
  than 4096 device blocks alive at once left memory allocated after it
  ended. The memory that the runtime keeps for reuse is now bounded in
  bytes, given back to the driver when an allocation would otherwise run
  out of memory, and given back on request by `mdir.trim_device_memory()`.

## What else a user sees

- `MDIR_DEVICE_POOL_BYTES` and `MDIR_FFT_PLAN_BYTES` bound the idle blocks
  of the device pool (half of the device by default) and the workspaces of
  the cached cuFFT plans (a quarter) ([docs/environment.md](../environment.md)).
- `mdir.trim_device_memory()` and `sim.tunables.snapshot()` are new Python
  calls ([docs/python-segments.md](../python-segments.md),
  [docs/python-tunable.md](../python-tunable.md)).
- The CMake option `MDIR_BUILD_TESTS` (on by default) builds the tests and
  `mdir-opt`; the wheel turns it off, so a wheel builds from the sdist
  ([docs/building.md](../building.md)).

## Installing

- **The binary tarball.** `mdir-0.2.1-manylinux_2_28_x86_64.tar.gz` runs on
  Linux x86-64 with glibc 2.28 or later: RHEL, Rocky, and Alma 8 and later,
  Ubuntu 20.04 and later, Debian 11 and later. Extract it anywhere and run
  `bin/mdir doctor`. It carries HDF5, cuFFT, the OpenMP runtime, and
  libdevice, so a GPU run needs only an NVIDIA driver that supports CUDA
  13.0; no CUDA toolkit (D177, [packaging/README.md](../../packaging/README.md)).
- **The Python wheels**, for CPython 3.10 to 3.13 on manylinux_2_28 x86-64.
  A wheel carries its runtime, libdevice, and HDF5; with the extra `cuda`
  it takes cuFFT and ptxas from NVIDIA's wheels, so a GPU needs only the
  driver (D228, [docs/python-package.md](../python-package.md)):

  ```sh
  python -m venv mdir-env
  mdir-env/bin/pip install "mdir-0.2.1-cp312-cp312-manylinux_2_28_x86_64.whl[cuda]"
  ```

  The `mdir` command comes with the tarball, not with the wheel. Before
  the release, each wheel was installed by pip into a fresh environment of
  its CPython and run on the CPU, and one of them on a GPU
  (`scripts/release/check-wheel-install.sh`, #641).
- **From source.** Build the source archive as [docs/building.md](../building.md)
  describes, and check the install with `bin/mdir doctor`.

## Upgrading from 0.2.0

- **Checkpoints.** The format is unchanged (format 1). A checkpoint whose
  integers are below $2^{53}$, which is every checkpoint except one with a
  seed of $2^{53}$ = 9,007,199,254,740,992 or more, continues as before. A checkpoint written by
  0.2.0 with a seed of $2^{53}$ or more recorded a rounded seed, and a
  continuation now refuses it as a change of the coupling: begin a new run
  from it (`[input] checkpoint`) instead of `--continue` (D347).
- **Control files** are unchanged: no key is renamed, removed, or newly
  refused.
- **On a GPU**, a long process may now give device memory back to the
  driver between runs; set `MDIR_DEVICE_POOL_BYTES` to keep more of it.

## Known limitations

As in 0.2.0, but for the packages, which this release has: one device per
run, learned potentials on one GPU, no polarizable models, triplet terms on
the CPU only, the deterministic mode without neighbor groups, free energy
by decoupling only, and no shear of the cell. The list is in
[CHANGELOG.md](../../CHANGELOG.md), [0.2.1], Known limitations.
