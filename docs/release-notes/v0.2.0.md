# MDIR 0.2.0

The second release of MDIR. With it the Python API (milestone M2a) is
complete. It also has the first parts of differentiable simulation (M2b),
learned potentials (M3), and distributed execution (M4). This release is
source only: there is no binary tarball and no wheel (see Installing).

## What MDIR is

MDIR is a compiler for molecular dynamics, built on MLIR. A run is written
in dialects of molecular dynamics, and MDIR compiles it for the system at
hand, just before the run. It derives the forces and the virial by
semantic differentiation, chooses the neighbor structures, storage, and
precision, and lowers the result to the CPU with OpenMP or to an NVIDIA
GPU. There are two front ends: the driver `mdir`, which reads a control
file in TOML with Amber, GROMACS, or CHARMM inputs, and the Python package
`mdir`.

## What is new since 0.1.0

The full list, with the decision behind each change, is in
[CHANGELOG.md](../../CHANGELOG.md), section [0.2.0].

- **The Python API (M2a).** `mdir.compile` builds a program from Amber,
  GROMACS, or CHARMM inputs. `mdir.Simulation` runs it across any number of
  `run(n)` calls, to the bit of `mdir run` in the deterministic mode. The
  API has reporters, checkpoints that either front end continues,
  minimization, DLPack views and writable borrows of the device buffers,
  topology views, and OpenMM quantities. Every key of the control file has
  a Python counterpart: thermostats, barostat coupling and work, the
  neighbor structures, PME settings, `observe`, and terms of the absolute
  positions ([docs/python.md](../python.md)).
- **Differentiable simulation (M2b, in progress).** Tunable parameters
  change without recompiling. The derivative of the energy in them, PME
  charges included, comes from `Simulation.tunables.gradient()`. The
  frame evaluator gives energies, gradients in the positions and the
  strain, and derivatives in the tunables at stored frames, also as an
  operation of PyTorch for fits by reweighting
  ([docs/python-frames.md](../python-frames.md)). H5MD trajectories store
  frames without loss.
- **Learned potentials (M3, in progress).** A TorchScript or AOTInductor
  model of metatomic runs through an optional plugin on one GPU, with
  minimization and stochastic cell rescaling
  ([docs/metatomic-ml1.md](../metatomic-ml1.md)). Neural models in stages,
  which MDIR compiles and differentiates itself, run pretrained PaiNN on
  one GPU ([docs/ml4-ir.md](../ml4-ir.md)).
- **Distributed execution (M4, in progress).** The dialect `md_dist`, its
  verifier, and its derivative run on an in-process reference executor. No
  run takes it yet ([docs/distributed-ml2.md](../distributed-ml2.md)).
- **Speed and memory on a GPU.** The neighbor structure is chosen
  automatically (`neighbor_structure = "AUTO"`, the new default). The
  skins of the neighbor lists can be chosen by measurement
  (`pairlist_distance = "AUTO"`). PME spreads through tiles of block
  memory. The tuple structures are ragged, and the PME and neighbor
  buffers are shared, so one 24 GB GPU now runs STMV replicated to about
  16 million atoms.
  Checkpoints are written on a thread beside the steps.
- **Physics and numerics.** A second PME kernel, Ewald summation with
  prolates (`[pme] kernel = "PROLATE"`), and the P3M influence function.
  A force tolerance for minimization. A temperature estimate with
  constraints after Jung, Kobayashi, and Sugita (2019). Shifted potentials
  in the free-energy and observables files.
- **Inside the compiler.** Typed, set-bearing storage buffers; declared
  transposes for every `md` op; a semantic FFT transform and its storage;
  shared device emitters for scans, compaction, reductions, and
  scatter-accumulates; and an opt-in single-pass device scan for group
  builds. None of these changes results or keys.
- **Defects of 0.1.0 fixed.** Among them are the lost pairs of #258
  (triclinic cell, neighbor matrix, constant pressure) and #263 (groups,
  long pairlist distance), steepest descent on rigid water, the dispersion
  correction of `[[energy.pair]]` terms, and the memory growth of long runs.

## Installing

0.2.0 has **no binary tarball and no wheel**. Build it from the source
archive of the release, `mdir-0.2.0-source.tar.gz`, as
[docs/building.md](../building.md) describes:

1. Build LLVM/MLIR 23.1.2 and HDF5.
2. Build MDIR with CMake. Add `-DMDIR_ENABLE_PYTHON=ON` for the Python
   package, and `-DMDIR_ENABLE_METATOMIC=ON` for the plugin of learned
   potentials.
3. Run `cmake --install build --prefix <prefix>`, then check the result
   with `<prefix>/bin/mdir doctor`.

The container recipes in `packaging/` build from the same sources. A GPU
build needs a CUDA toolkit and an NVIDIA driver.

## Upgrading from 0.1.0

The checkpoint format is unchanged (format 1). 0.2.0 reads and continues
the checkpoints of 0.1.0; the entries it adds are ones that 0.1.0's reader
ignores. No control-file key is renamed or removed. What changes for a
control file of 0.1.0:

- **The neighbor structure.** A large system on a GPU now runs on the
  groups of 16 with a dual list. To keep 0.1.0's choice, set
  `[execution] neighbor_structure = "MATRIX"`.
- **Newly refused inputs.**
  - A constant named `observe` in a term given by an expression is
    refused, since `observe` is now a reserved key: rename the constant.
  - A custom term parameter whose name collides with a name the term
    supplies is refused: rename it, for example `r` to `r0`.
  - `--continue` of a one-state `[free_energy]` run onto a file written by
    0.1.0 stops at the file's header: use `--no-append`.
- **Outputs.** A one-state `[free_energy]` run no longer writes the
  `dU.0` column. Under a plain cutoff the free-energy and observables
  files take the shifted potential.
- **Numbers that change.**
  - With constraints, the temperature of the log reads 1 to 2 K higher at
    2 fs, and leapfrog with constraints follows velocity Verlet.
  - Deterministic trajectories change.
  - Steepest descent caps its step at 0.1 Å and stops when the step
    shrinks below a floor.
  - A constraint failure stops the run.
- **Python.** The Python API is new in 0.2.0: 0.1.0 had none, so there
  are no scripts to upgrade. The Python entries under Changed in the
  changelog describe changes made during this release's development.

## Known limitations

The list is in [CHANGELOG.md](../../CHANGELOG.md), [0.2.0], Known
limitations. In short:

- There are no binaries in this release.
- A run uses one CPU or one GPU. Distributed execution does not run yet.
- Learned potentials run on one GPU, with refusals listed in the
  changelog.
- There are no polarizable models.
- Terms over triplets run on the CPU only.
- The deterministic mode keeps the neighbor matrix.
- Free energy is limited to decoupling.
- The barostat does not shear the cell.
