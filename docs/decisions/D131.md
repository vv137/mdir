# D131

Recorded 2026-10-02.

**SIGTERM, SIGINT, and `--max-walltime` stop a run of dynamics at its next checkpoint, with the exit status 75.** The stop is taken in the function of the driver that writes a checkpoint, after the write, by ending the process: the state on disk is the one that the loop of segments carries on with, so the run continues from it exactly (R1), and the schedule keeps its loops of constant counts at no cost per step or per segment. (The roadmap had a host call return a flag that the loop of segments tests; ending the process from the call does the same without a change of the compiler. The Python API, which runs segments from the host, will stop between them.) The handler of a signal sets a flag and is reset (`SA_RESETHAND`), so that a second signal of the same kind ends the run at once; no stop is taken at the last step. `--max-walltime`, in hours or as `H:MM[:SS]`, stops at a checkpoint when the time since the driver began plus the longest interval between checkpoints so far would pass it. 75 is `EX_TEMPFAIL` of `sysexits.h`, a failure that a later attempt gets past, which a script tells apart from 0, a run that is complete, and 1, an error. A run without checkpoints, and a minimization, keep the default handling of the signals and refuse `--max-walltime`. The checkpoint at the stop is that of a run of as many steps that was not interrupted, bit for bit (`test/Driver/stop-signal.test`).
