# D321

Recorded 2026-10-22.

**The group neighbor build may use an opt-in single-pass integer scan with decoupled look-back, while its three-launch scan remains the default.** #524, part of #420. Active blocks claim consecutive tiles, publish an aggregate, look back to a completed prefix, and publish their own prefix; a single i64 atomic descriptor packs phase and i32 sum so no reader pairs a new phase with an old sum [[MerrillGarland2016]](../references.md#merrillgarland2016). The scan uses one initialization launch and one scan launch, reads each count once, and writes the same exact offsets and optional cursor as the three-launch strategy. The `convert-md-exec-to-gpu` option `single-pass-group-scan=true` selects the alternate group template generated from the same source; no control-file key changes. *Validation*: the device primitive matches a serial CPU prefix exactly for empty input, 5,000 counts with and without a cursor, and 131,083 counts; the EAM group GPU test checks double and mixed precision against its independent reference; memcheck and racecheck found zero errors. *Measured* (RTX 4090, mixed): the three JAC scan groups took 52.65 → 38.41 µs per build, and the STMV groups 95.12 → 80.83 µs. Whole-step Amber medians (main → strategy, ms/step): JAC NVE 0.135785 → 0.136091, Cellulose NVE 1.136844 → 1.135727, STMV NPT 4 fs 3.797802 → 3.818826; a JAC run with 0.5 Å outer and 0.2 Å inner skins and 4,594 builds in 10,000 steps took 0.188103 → 0.186177. With no end-to-end gain in ordinary Amber runs, the default stays the three-launch strategy.
