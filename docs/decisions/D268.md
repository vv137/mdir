# D268

Recorded 2026-10-16.

**The pruning of the inner list of the groups (D114) stays global and exact; the loop over groups takes only the active units, the blocks that a pruning left with entries, listed by the pruning in the order of the blocks with their number on the device; the index of the blocks of each group is made at the build; the kernel of the frames of a pruning copies its configuration; a loop over pairs that follows a pruning at the same positions in f32 takes its frames.** The maintainer's ruling on PR #360 (#357). *Measured first* (RTX 4090, mixed precision, groups 12 / 9.6 Å; [scripts/benchmarks/rolling-prune](../../scripts/benchmarks/rolling-prune)). A pruning of 103,292 TIP3P waters took 224 µs every 2.4 steps: its main kernel 200.5, the index of the blocks 7.4, the frames 7.3, the copy of the configuration 8.7; of the main kernel, reading the outer list 78 µs, the gather 26, the 16 tests about 55, the stores 42. After a pruning about 40% of the units are empty. *Not taken, measured*: the tests in the expanded form +2%, a test against the box of the group first +7%, 2 lanes a candidate +23%, 4 lanes +109%; a pruning of each group on its own exact trigger, which costs more than it saves (TIP3P 1140.8 against 1123.6 µs a step); a bound over the groups within reach, at most about 20 µs a step and a structure that does not exist. A pruning fused with the loop is #362. *Implemented*: the active units in the order of the blocks (in the order of the groups the loop took 576 µs against 526, the warps of one group running together), counted in runs of 32 and 1024 blocks and placed by one kernel; the count cleared by each pruning, so that a build that places no particle (D107) leaves none; the copy of the configuration in the order of the particles in the kernel of the frames (13.0 µs with the frames; scattered by place 20.9, in the main kernel +17). *Measured* against main (µs a step, 5 rounds): TIP3P 1130.4 → 1118.2, OPC 1633.0 → 1612.8, JAC 137.0 → 135.4, ubiquitin in OPC 182.2 → 180.4, STMV 4784.2 → 4737.0. The forces at the start differ from main's within main's run-to-run noise. `MDIR_CHECK_PRUNING` (the option `check-pruning`) counts at each step the pairs within the cutoff in the outer list and in the inner one through the active units, and stops the run if they differ (`prune-check-gpu.test`; a reach 0.98 times too short and one active unit dropped both stop it). No key, format, or default changes; the sums depend on the order of the threads as before, and the deterministic mode does not take groups. The ideas of the active-unit index and of sharing the frames come from an external review.
