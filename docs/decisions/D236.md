# D236

Recorded 2026-10-08.

**A `Program` keeps the code of its simulations in memory: the first `mdir.Simulation(program)` leaves the bitcode of the LLVM module of its program of segments and the host object of that module with the `Program`, and a later simulation with the same key parses the one and links the other, without the MLIR pipeline and without host code generation.** Issue #236. Every simulation of a program lowered and generated its code again, whether or not the compile cache was on (the cache saves the generation only, D212). What is kept is not `Program.lowered_ir`: a simulation lowers a program of segments of its own (D215), built from the model, and that one's code is kept. The key is a hash of what the lowering and the code generation read: the text of the module that the builder gives for the simulation, built anew each time; the pipeline with its options (the width of the neighbor structures, the precision, the threads, and on a GPU the architecture, the binary format, and `cache=false`); the name of the entry; and the description of the machine and the code generator of D212. A simulation whose key differs lowers anew. The LLVM module is kept beside the object because an engine reads the constructors of a module (which load the kernels of a GPU) from its IR, as on a hit of the disk cache; the kernels' cubins are constants of the object, so a GPU needs nothing of its own. Each engine links its own copy (D199). The store is freed with the `Program`, is independent of `MDIR_COMPILE_CACHE_DIR` and `MDIR_COMPILE_CACHE`, and is bypassed, for reading and for keeping, by `cache=False` (D217), which means "generate everything anew". `compile_stats` has `program_reused` (0 or 1) and `reuse_saved_seconds`; with `program_reused`, `pipeline_seconds` and the counts of the host and GPU caches are 0. Rejected: keeping the lowered MLIR module (its context is not shared between threads, and its translation to LLVM IR would be repeated), and linking the object without its module (the constructors would not run).
