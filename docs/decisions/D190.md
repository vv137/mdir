# D190

Recorded 2026-10-04.

**With one state, `[free_energy]` writes $\partial U/\partial\lambda$ alone.** The difference $U(\boldsymbol\lambda^{(0)}) - U(\boldsymbol\lambda)$ of the only state is identically 0, so the file has no `dU.<k>` columns and the builder no longer evaluates `@alchemical` at the states, only its derivatives at the run's state; two or more states are unchanged, bitwise. A one-state set defines global parameters for their derivatives (Appendix C.9). The column header of D149 makes `--continue` onto a file of the old layout stop, so the change needs `--no-append` or a new file. `scripts/free-energy.py` refuses a file without `dU` columns, as thermodynamic integration and MBAR need two or more states. *Evidence.* On ethanol in TIP3P (`test/Driver/free-energy.test`, CPU double), the three-state file and log are byte-identical to main's, and a one-state run at $\lambda = 0.5$ gives the `dHdl` columns and the log byte-identical to main's; on a GPU in mixed precision the same run gives them within $9\times10^{-6}$ kcal/mol. Issue #71.
