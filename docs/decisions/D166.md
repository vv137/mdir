# D166

Recorded 2026-10-03.

**MLIP support starts with one existing model through an optional metatomic adapter on one GPU, then validates that same local model on two GPUs partitioning one physical system; staged message-passing optimization follows.** Adopted 2026-10-03 as a development plan, not implemented functionality. Classical MD remains an independent core use case, with its existing features, validation, and performance baselines preserved; LJ/EAM are initial distributed validation models, not a limit on the final scope. This amends D1 only to let the opaque adapter start before the distributed compiler and full Python API. Reuse community model artifacts and an external tensor backend behind a versioned potential/neighbor contract; keep MDIR's compiler types and ABI independent, and classical builds free of required Torch/metatomic dependencies. The adapter declares units, species, requested outputs, particle/image identity, output-specific support, derivative ownership, and buffer lifetime/completion; energy support alone cannot establish a force halo. Validate energy, every particle's force, and stress/virial against the original backend, with coordinate/cell finite differences and short NVE runs. Build distributed ownership, coverage, freshness, a verifier, and reverse contribution routing on two-domain LJ and EAM before using them for the local MLIP. The first scope is finite-range local interactions, one node, a fixed cell, and no constraints; one/two-GPU correctness completes the deliverable, while four-GPU scaling follows separately and a cluster claim needs multiple nodes. The compatibility path remains usable when one message-passing model gains stage hooks or semantic import. Compare enlarged coordinate halos with per-layer feature exchange using identical weights, precision, and outputs, counting reverse communication, redundant work, memory, and full-step time; no strategy is assumed faster. Intermediate-feature communication and model deployment already have precedents: the research candidate is deriving, verifying, and selecting legal executions from energy/derivative dependencies, not merely accepting MLIP files. Defer arbitrary model import, training, distributed PME, global model operations, and cross-domain constraints. Keep publication of the classical first milestone independent of this extension. Detailed contracts and validation: [architecture plan](../future-architecture-plan.md#adopted-scope-and-first-deliverable); milestones ML1–ML5: [roadmap](../roadmap.md#7-learned-potentials-m3-and-distributed-execution-m4).
