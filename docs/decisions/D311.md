# D311

Recorded 2026-10-21.

**`MDIR_DEVICE_MEMORY=2` breaks the device memory of a run down by where it goes** (#471, step 1). The runtime reads the driver's use of the device (`cuMemGetInfo`, every process on it) once the context is made, at the peak of its pool, and around each event that may take memory outside the pool: the loads of modules, the first launch of each kernel (the driver's local memory), cuFFT's plans, cuBLAS's handle, the store of the structures of the tuples, the constants of the bodies, and memory shared with the host; it records, by account, the growth against the bytes asked for. It keeps the blocks of the pool at its peak in use and at its peak with the pool, each with what it was allocated for (a buffer of the groups or the matrix, a structure of the tuples, or compiled code), and prints them by size. Each incidence structure of the tuples is printed with its width as it is made. Without the value `2` nothing is read or kept; `1` prints the two peaks of D294 as before. No control-file key or output change. *Validation*: on STMV (RTX 4090, mixed, 1,000 steps), the accounts add up to the driver's use at the peak within 2 MiB, which agrees with the peak that `nvidia-smi` sampled for the process within 9 MiB; the peaks of a run with `1` are those of a run with `2` within the variation of the pool between runs (the numbers are on #471).
