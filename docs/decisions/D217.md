# D217

Recorded 2026-10-07.

**`mdir.clear_compile_cache(directory=None)` removes the entries of this format from the directory given or from `MDIR_COMPILE_CACHE_DIR` and returns what it removed; `cache=False` on `mdir.compile` (keyword only, recorded in the program) and on `Simulation(program, cache=None)` (keyword only, `None` takes the program's choice) bypasses the cache for one compile, and `compile_stats["cache_bypassed"]` reports it.** Issue #163, left open by D212; the maintainer's decisions on PR #172.<br>*Clear.* `clearCache` lists `host/*.o`, `gpu/*.ptx`, and `gpu/*.cubin` and removes a file only if its first 8 bytes are this format's magic tag; entries of another format, other names, the directories, and the temporary files of writers under way (so that their renames succeed) stay, and temporary files older than an hour go, as in eviction. `MDIR_COMPILE_CACHE=off` does not hide the directory from it. The result is `{"directory", "host_entries", "gpu_entries", "bytes"}`. MDIR keeps no entries in memory between compiles, so there is nothing else to clear. Writers rename complete entries into place and readers copy files, so a clear during other processes' compiles can cause a miss or a lost store, never a partial entry.<br>*Bypass.* `JITEngine::create`, `compiler::compile`/`lower`, `getGpuOptions`, and `Simulation::create` take a `cache` flag; `mdir-gpu-module-to-binary` and `mdir-gpu-lower-to-nvvm` gain the option `cache` (default true), which a bypassed GPU program shows in its pipeline. Bypassed, the host object cache has no directory (it only times code generation) and the GPU serialization reads and writes no entry and evicts nothing. It is on both functions because `mdir.compile` lowers a program of its own that reads and writes GPU entries before any simulation exists.<br>*Not chosen:* clearing every entry file whatever its format (a directory may be shared by builds of another format); a `clear_compile_cache` without a directory argument.<br>*Evidence.* The dipeptide in water (PME, SHAKE, SETTLE, deterministic, mixed), one process per scenario, on the CPU and a GPU (`compile-cache-controls{,-gpu}.test`): `cache=False` on an empty directory makes none; on a warm one it generates every host object, PTX, and cubin, hits nothing, leaves every entry with its size and modification time, and gives the state of no cache bit for bit; `Simulation(program, cache=False)` after a compile that used the cache does likewise; `cache_bypassed` is 1. A clear removes the host object and every GPU entry of the warm cache and keeps a file of another format and a writer's temporary file; the next process misses and stores, the one after hits. While one process cleared about 190,000 times, another compiled four times on the CPU, each a miss and a store; the entries left were well formed and the next process read them with no rejection. `compile-cache.test` races `clearCache` against a forked writer of 3000 entries: 85 clears removed 2947, every write succeeded, and the 14 left were intact. See [compile-cache.md](../compile-cache.md#controls-from-python).
