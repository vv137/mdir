# D118

Recorded 2026-10-02.

**The flags that kernels set are memory of the host mapped for the device, which the runtime reads after an event and clears as it reads; each loop that sets a flag has one of its own.** Before, a flag was memory of the device: `mdrtFlagStart` copied it to pinned memory of the host and recorded an event (D113), and where it was set the lowering cleared it by a copy of a zero from the host. On ubiquitin in OPC (nsys, NVE, 20,000 steps) the device stood idle 49 µs of a step of 310. The two copies of the flags of the dual list held it some microseconds each between the test of validity and the reciprocal sum (13 µs a step): a copy between two kernels of one stream starts and ends late. The clear went through `mgpuMemcpy`, which waits for the whole stream after a copy from the host, so every pruning of the inner list (one step in three) waited for the reciprocal sum issued before it and left the device idle while the host then issued the pruning (15 µs). Now `mdrtFlagMemory(place)` gives each place of the module that takes a flag a word of memory of the host allocated with `CU_MEMHOSTALLOC_DEVICEMAP` and clear, the same at every call of its function; a kernel stores 1 into it across the bus, `mdrtFlagStart` records an event, and `mdrtFlagFinish` waits for it, reads the word, and clears it. No kernel that sets a flag is issued between the read and the decision that uses it, so the clear of the host is safe. A flag read so is read after the kernels issued before the read, not at its place in the stream: when loops shared a flag by its number within the loop, a later loop could set it first, and `minimize-gpu.test` and `not-numbers-gpu.test` failed at random under the load of the whole suite; each loop now takes a flag of its own. **Measured** (RTX 3090 at 300 W, one run each): ubiquitin NVE 585 to 609 ns/day, the device idle 29 µs of a step; JAC NVE 770.9 to 817.7, JAC NPT 703.2 to 754.9, FactorIX NVE 284.3 to 291.5, Cellulose NVE 62.4 to 63.2 (the means of Table 10.2 before). The reciprocal sum on a second stream (D81, D87) still lengthens the step (597 against 609 on ubiquitin). The whole suite passed three times in a row. **Claim.** The value that `mdrtFlagFinish` returns is the value the flag had at its place in the stream, after the loop that sets it. **Premises.** (P1) Only that loop sets the flag: each loop that reduces to a flag takes a new one from `getFlag(flags.size())`, and the number of its place in the module from `mdrtFlagMemory` (the lowering). (P2) No launch of that loop is issued between `mdrtFlagStart` and `mdrtFlagFinish`: both are in the block of the loop, the finish before the first use of the flag in that block (`replaceWithFlag`), and straight-line code issues the loop once. (P3) A store of a kernel to mapped memory of the host is visible to the host once an event recorded after the kernel has completed, and a store of the host is visible to a kernel launched after it: true of pinned memory mapped with `CU_MEMHOSTALLOC_DEVICEMAP` on x86-64 with this driver (595.84) and an RTX 3090, where it was checked; a platform where mapped memory of the host is not coherent needs the copy of D113 back, which `mdrtFlagStart` keeps for a pointer outside the mapped words. The CPU lowering reduces flags as integers in its loops (`MDExecToLoops`) and is not affected.
