# D223

Recorded 2026-10-07.

**A Python simulation writes the checkpoint of `mdir run` and continues one written by either front end, keeping D172's distinction between the same run and a new stage; the fingerprint of a Python model holds the entries that the control file of the same model writes, and format 1 gains entries that earlier readers ignore.** Issue #132, M2a item 5. `Simulation.save_checkpoint(path)` and `CheckpointReporter(file, period)` write format 1 through `writeCheckpoint` on the host (`.prev`, durable replacement, D173); a simulation that has not run evaluates its start first, and the next part begins a new activation from the state written, as `mdir run` builds its structures anew at each checkpoint, so that going on and continuing the file are the same steps. `Simulation(program, checkpoint=path)` continues the same run as `--continue` does: it refuses other physics or coupling (naming each entry), other tunable declarations, another integrator, particle count, or types, and a checkpoint without forces (`InputError`); other execution is a `UserWarning`. It takes step, time, positions, velocities, forces, cell, bath, and the values, version, and history of the tunables. `stage=True` begins a stage as `[input] checkpoint` does: step and time continue, the bath restarts, and the forces are taken only with equal physics and coupling; otherwise the first part begins with `%first_call = 2`, whose leapfrog half kick back the program of segments now selects for every leapfrog program, not only one with tunables. `append=True` keeps the rows of the energy file through the checkpoint and cuts the trajectory it counts to its frames; `append=False` writes `<name>.partNNNN<ext>` (D149). `mdir.read_checkpoint` returns a read-only view; without HDF5 each use raises `UnsupportedError`. Fingerprint (maintainer's decision on PR #186, option 1): an entry for a setting given explicitly on the Python objects or whose Python default differs from the control file's value for an absent key (`switch_distance`, `pairlist_distance`, `center_of_mass_interval` under a thermostat), the method keys that `Ensemble.kind` implies, control-file names, units (Å, kcal/mol/Å², atm), and canonical text; the topology files hashed as `mdir run` hashes them (not the coordinates), the masses, and the reference of restraints; `[python] pair_terms`, `[python] tuple_terms`, and `[python] tunables` for what has no key, so `mdir run --continue` refuses a checkpoint with them and begins a stage from it. Additional entries of format 1: `front_end`, `model_sha256`, `plan_sha256`, and `tunables/`, outside `state_sha256`, with `extras_sha256` checked when present; no migration and no Changed entry. *Evidence* (`python-checkpoints-*.test`, dipeptide in water, deterministic, CPU and RTX 3090, double and mixed): `mdir run` -> Python and Python -> `mdir run --continue` at step 10 of 20 equal the uninterrupted run to the bit in NVE, NVT, and NPT with PME and constraints, with energy file and DCD byte for byte; Python -> Python with tunables updated equals the run going on after `save_checkpoint`; stages with restraints, another temperature, NPT, and leapfrog equal `mdir run` from `[input] checkpoint` to the bit; corrupted state, corrupted additional entries, truncated and non-HDF5 files are refused.
