# D129

Recorded 2026-10-02.

**`steps` is the length of a run, and `mdir run --continue` continues the run from its own checkpoint until it has taken them; a run that begins from the checkpoint of another begins at its step.** A checkpoint records the step that its run began at (`first_step`), its part (1 for the first, one more for each continuation), and the energy that the coupling of the velocities has taken since the run began (`bath`). `--continue` reads the checkpoint of `[output]`: with none the run begins, so that the same command line starts a run and resubmits it until it is complete; with one the run takes the steps that remain to `first_step + steps`, and a run that is complete says so and exits with 0 without compiling. It refuses a checkpoint of another time step or seed, steps that remain if they are not a multiple of each interval of output and of the coupling (counted from where the run began), and a checkpoint that does not record its run. A run that begins from the checkpoint of another (`checkpoint` of `[input]`, the stages of `examples/`) is a new run whose step and time continue from it: the key of the random numbers holds the step (A13), and stages that began at step 0 with the same seed would draw the numbers of the stage before. So `steps` means what it meant for every run that begins; what is new is that the same run continues to its total, which an extension raises. The conserved energy of a continued run counts on from `bath`, and its rows are those of the run that did not stop (`test/Driver/continue-gpu.test`).
