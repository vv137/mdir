# D149

Recorded 2026-10-03.

**The outputs of a run form one system: `[output]` names every file and its interval, the files of columns share one form, every file continues with the run, and a run that is not continued keeps the outputs of an earlier one as backups ([driver.md](../driver.md), Section 2.8).** The keywords: `log` (the log in a file as well as on the standard output), `energy` (the rows of the log as columns), `pull` (the terms over centers of D145, which was `pull_coordinates` and holds their energies and forces besides the coordinates), `trajectory`, `trajectory_format`, `checkpoint`, and the three intervals; the files of columns are written at `energy_interval`, the only steps at which the compiled schedule computes energies. A file of columns has a line of names and a line of units, one for each column (`-` for none), then a row for each output, the step an integer and the rest with six decimals; the units line of D145, one for all columns, became one for each. A continued run keeps the rows of a file of columns up to the step of its checkpoint and appends, as the trajectory keeps its frames (D130), and refuses a file whose first two lines are not the ones it writes; the log file is appended whole, since it records what happened. `--no-append` sends the log, the energies, the terms, and the trajectory of the continued part to `<name>.partNNNN<ext>`, and the checkpoint records that part (`outputs_part`, 0 for the names of the control file) for later continuations; a checkpoint without the record cannot be continued. `mdir run` without `--continue` keeps each output that exists, the checkpoint before the last (`.prev`) included, as `#<name>.<n>#` in its directory, n the least number from 1 that no file takes, and the log names each backup; a stage run twice by mistake does not destroy the first, as GROMACS keeps its files [[GromacsManual2025]](../references.md#gromacsmanual2025). It keeps at most 99 backups of a file and stops before it writes, or moves any file, when one more would be needed. Under `--continue` the files belong to the run and none is backed up. Two outputs with one name, or an output with the name of an input, are errors of the control file. The preflight of `mdir check` (D151) lists these outputs in this order, with the number of rows, frames, or checkpoints of the whole run (`count` and `count_of` in its JSON), and a note for each output that exists with the name that a run keeps it under (`outputs[].backup` and `notes` in its JSON, additions to schema version 1), or a warning when 99 backups are taken. Not taken: a run that refuses to begin while an output exists, with an option to write over it, which the user reviewed and replaced with the backups (2026-10-03); intervals of their own for the files of columns, which the schedule would need loops for.
