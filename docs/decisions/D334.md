# D334

Recorded 2026-10-22.

**Verified execution uses one shared contract for provenance, effects, validity, and state-specific witnesses across `md`, `dyn`, `md_exec`, and `md_dist`.** #574, design only. Invariant meaning belongs in types or static attributes; changing state belongs in SSA values and explicit operands. A required condition is proved or guarded with legal recovery; if unresolved, its path is not executed and an unsupported-contract diagnostic is issued. Refuted required conditions, contradictory types, mismatched entities, invalid evidence, and demonstrated uninitialized reads are invalid IR. An unavailable optional strategy uses an independently legal baseline with an `explain` reason. `Unknown` implies no positive fact; a predicate is not a witness and an available event is not completion. Existing user inputs keep the diagnose-through-`mdir check` rule. Numerical requirements are distinct from access requirements but are also prerequisites of a legal plan: a race-free atomic sum is illegal when fixed order is required. The design conditionally verifies supported contracts under named rules and recorded assumptions, with predicate rules and numerics, effect and derivative models, preservation arguments, accepted external contracts, the runtime, backends, and toolchain in its trusted base. The plan chooses by measured cost only among legal strategies. This documentation PR defines the shared architecture for #565, #566, #567, #571, #572, and #573; it adds no op, control key, file format, runtime check, strategy default, or emitted-code change. Later refactors retain lowered IR and PTX byte-identically and deterministic outputs bitwise identically.
