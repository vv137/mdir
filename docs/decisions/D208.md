# D208

Recorded 2026-10-06.

**The test suite runs at most sixteen tests that need a GPU at once by default (`gpu_workers` of `test/mdir_lit.py`), and no Python test runs all its scenarios in one file.** Issue #141. Most tests that need the device spend their time compiling on one core of the host and leave the device nearly idle (0.3% mean use in `python-segments-gpu.test`), so the bound of four (PR #83) set the wall time, and three Python files of 490 to 670 s each were its critical path. `python_segments.py` and `python_velocities_restraints.py` take a scenario, and each scenario is a test file on the CPU and on a GPU; `python-simulation-lifetime` runs each import order in a file of its own. Every check is in exactly one file; a scenario that needs another's reference (the uncoupled NVE run, the NVT run of `mdir run` in double precision) computes it again without checking it. *Evidence.* `check-mdir`, Release, Python on, one RTX 3090 (300 W) and a 128-core host shared with other users: before the split 1089 s with 4 and 691 s with 12; after it 969, 496, 370, and 262 s with 4, 8, 12, and 16, where 262 s is the slowest test (`free-energy-gpu.test`, about 240 to 260 s), so a larger bound gains nothing; a repeat with 16 under a load average of 94 took 340 s. With 16 the device held at most 4.2 GB. The sanitized suite (`scripts/build-sanitized.sh`) keeps four, which was not measured again.
