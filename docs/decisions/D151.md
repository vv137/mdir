# D151

Recorded 2026-10-03.

**`mdir check` is a read-only preflight, with a JSON report** (2026-10-03, U6). It uses the same control and system readers as a run and reports the planned ensemble, steps, duration, PME, constraints, target, precision, and every output with its path, format, interval, enabled state, and existence. Before, a topology input returned after the topology summary, omitting the run; both topology and PDB inputs now get the run summary. One inspected list supplies output metadata and warnings to text and JSON. Existing enabled outputs, fixed neighbor-rebuild intervals, absent energy reports or checkpoints, missing input checkpoints, and missing HDF5 or CUDA build support produce actionable warnings, with exit status 0; invalid input retains exit status 1. `--json` writes one object to standard output, including on errors, with schema version 1 and warnings identified by codes. The check neither writes files nor compiles, probes a device, or loads a checkpoint: it can inspect future stages before their input checkpoints exist, and its length is the configured stage length, not the remaining work. Automatic PME settings stay explicit; minimization has no physical duration, and a nonperiodic system has no physical cell or density. `preflight.test` covers the text and JSON, errors, all ensembles, minimization, PME, PDB and topology inputs, nonperiodic cells, disabled outputs, quoted paths, and unchanged existing output files.
