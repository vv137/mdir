# D130

Recorded 2026-10-02.

**A continued run appends its frames to the trajectory that its checkpoint counts them in, cut to those frames.** The checkpoint records the file name of the trajectory and the frames it holds at that state. `--continue` checks the header of the file (written by MDIR, the number of particles, the interval of frames), refuses if the file holds fewer frames than the checkpoint counts or is missing while it counts some, removes the frames past the checkpoint (those that a run wrote before it ended between checkpoints), rewrites the count of the header, and appends. With `--no-append` the frames that follow go to `<trajectory>.partNNNN.dcd`, NNNN the part of the run, which later continuations append to. A trajectory that is stopped, cut back, and continued is that of the run that did not stop, byte for byte (`test/Driver/continue.test`).
