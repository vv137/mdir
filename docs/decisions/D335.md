# D335

Recorded 2026-10-22.

**A checkpoint of `mdir run` keeps ending its segment: the next segment begins in a new order of the particles and builds its structures anew, on every target and in every mode. Keeping the order and the structures across a checkpoint was measured and not taken.** #548, part A of its plan (the maintainer, 2026-10-22). *The breakdown* (`MDIR_CHECKPOINT_TIMES=1`, which this decision adds; one RTX 4090; the suite's output of `bench.py --suite-protocol` with the default reaches, files on the shared file system; the mean over the checkpoints inside the windows of three runs). STMV: the copy from the device 8.6 ms, the order of the input 48.7 ms, the SHA-256 of the state 311.3 ms, the H5MD file to its close 114.6 ms, its `fsync` 0.3 ms, the `.prev` and the rename 0.2 ms, the `fsync` of the directory 0.1 ms; the DCD frame of the same step 4.4 ms of copy and 48.1 ms of write; the start of the next segment, derived from the rows every 100 steps of a run of its own (the interval over the checkpoint less the frame, the checkpoint, and the median interval), about 35 ms. Cellulose (NVE and NPT alike): 4.0, 6.4 to 6.9, 119.6, 43.1 to 46.1, 0.3, 2.6 to 3.0, and 0.1 ms, and a frame of 1.2 + 8.5 ms. The hash and the file were 85% of a checkpoint on STMV. *Part A.* Where a run is the same to the bit from run to run (the CPU, the deterministic mode, and, as `continue-gpu.test`, `restart-gpu.test`, `langevin-gpu.test`, and `checkpoint-contract-gpu.test` show, the matrix on a device), the run continued from a checkpoint begins in the order of the positions it reads; keeping the order of the run that goes on would need the order and the neighbor lists in the file, which would change format 1. A was therefore tried only with the groups of 16, whose sums take atomic additions in the order of the threads: the checkpoint as a call of the host inside the steps, without `mdrt.segment` and with `mdrt.fresh` on the loop over checkpoints. It made the runs slower: in one job, alternated with main, STMV 77.13 ± 0.89 ns/day against 78.25 ± 0.48, Cellulose NVE 141.52 ± 0.31 against 143.49 ± 0.12, Cellulose NPT 134.56 ± 0.04 against 136.45 ± 0.17 (three repeats each). The new order of a segment restores the locality that the order of a long segment loses (Section 10.5 of the white paper): on STMV the 100-step intervals after the checkpoint took 381 to 391 ms with the new order and 388 to 392 ms without it, which outweighs the start of the segment, about 35 ms since D257 and D314. The program, the checkpoint file, and the continuation are those of main; the timers are the change.
