# D340

Recorded 2026-10-25.

**A device primitive has one operation and correctness contract, with backend-specific instruction emission and a single target record that separates capabilities from measured strategy policy.** #558, first stage, with #433 and #444. The source inventory in `docs/device-primitives.md`, Section 6, covers explicit NVVM operations and attributes, PTX inline assembly, generic GPU operations, and existing emitters. Required subgroup width, workgroup memory, arithmetic and atomic support, approximation accuracy, and load constraints are preconditions read by both chooser and lowering; a failed precondition gives an explain reason and a legal fallback. Measured thresholds and their overrides belong to the same target entry but cannot change legality. The generated group templates are maintained at their generator. Later PRs implement the target record, operation emitters, and runtime device interface one group at a time, retaining NVIDIA output. #433's proposed `CompilationPlan` records choices and reasons before building the unchanged pass pipeline; #558's proposed split of device lowering gives neighbor, interaction, collective, launch, and runtime code the same plan. These proposals remain future work. This decision changes documentation and header pointers only; no control key, API, file format, output, or performance path changes.
