### Changed

- **The skin search records its budget and candidates with its choice, and a later run reuses that choice** (D[skin-budget-record], #837). The cache of the skins (format 2) and the manifest's `skin_search` hold the budget, what it was computed from, and the candidates; the manifest says whether the run searched or reused, and why a run with a budget below 3 cached nothing. The log says `searched now`, `reused, not searched`, or, for a budget below 3, `not searched: the reference alone measured` with `not cached` and why. The key of the cache names the build (`mdir-skin-salt 1`): a clean build by its commit, LLVM, and the LLVM options, so `mdir` and Python of one clean build share a choice; a dirty build by its image's build ID as well, so it searches anew. Entries of format 1 are not read; `mdir check --json` gives the key (`run.skins.cache_key`), and so does `Program.plan["skin_cache_key"]`, where a run reads the cache, else null with the reason. An entry that is cut short or incomplete is refused, the log says so, and `mdir check` notes it (`skin_cache_refused`). `MDIR_SKIN_SEARCH=budget` searches within the budget whatever the length, for tests.
